# Initial Feasibility Study

## 1. Technical Feasibility

Our Campus Facilities Maintenance System is technically feasible because it can be developed using technologies and tools that are available to our team. The system will mainly require a user interface, a database to store maintenance requests and user information, and backend functionality to manage requests and status updates. Our team has experience with programming and software development tools, and we can learn any additional technologies needed during development. The project does not require specialized hardware, which also makes it easier to develop.

## 2. Economic Feasibility

The project is economically feasible because it does not require a large budget. We can use our existing laptops and free development tools for programming, testing, documentation, and version control. GitHub can also be used to manage and store our project files. Since this is a university project and prototype, we do not expect any major hardware or software costs. Any possible limitations would mainly involve access to certain paid services if they are needed later.

## 3. Operational Feasibility

The system is operationally feasible because it addresses a real problem on campus. Students and university staff need a simple way to report maintenance problems and track their requests. Maintenance staff and facilities administrators can also benefit from having requests organized in one system instead of managing them through less organized methods. The system is designed to be simple to use, so the intended users should be able to use and accept it without requiring extensive training.

## 4. Schedule Feasibility

The project is feasible within the available course duration because we selected the Incremental Model and can develop the system in smaller parts. We can first implement important features such as user login and submitting maintenance requests, and then add features such as request tracking, assignment, status updates, and notifications. Dividing the work among team members and setting deadlines for each increment will help us complete the major features and deliverables within the semester.

## 5. Overall Feasibility

Overall, the Campus Facilities Maintenance System appears to be feasible. It can be developed using the technical skills and resources available to our team, does not require a large budget, addresses a genuine campus need, and can realistically be completed within the course duration. The main constraints may include limited development time, technical difficulties when integrating different features, and the availability of team members. These constraints can be managed through proper planning, task distribution, regular communication, and testing throughout development.
